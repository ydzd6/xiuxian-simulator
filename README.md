# 修仙模拟器 · 一世一轮回

一个**零依赖、单文件**的中文网页文字修仙游戏。开局随机灵根与出身，测灵根、择宗门、闯秘境、结道侣，一路走到天门前——活出不一样的一世。

- 打开 `index.html` 就能玩，不需要服务器、不需要联网、不需要构建。
- 一局约 **5–10 分钟**，40 回合上下，112 个事件，六种结局，25 个成就。
- 双击即玩；也可以放到任意静态托管上，把链接发给微信好友。

> 🔗 在线版：<https://ydzd6.github.io/xiuxian-simulator/> —— 微信里直接点开就能玩。

## 玩法

### 一世流程

1. **取名**（不超过 8 字）、选性别。
2. **测灵根 + 定出身**——全部随机。一生只有**一次**「重开一世」的机会，用来改命。
3. 进入正文：每一回合是一个事件，事件里有 2–6 个选项。**所有选项都不提示后果**，你得靠正文的氛围和前因后果去判断。
4. 修为攒够时可以**闭关突破**（会消耗一个回合，有失败率，失败要拿寿元和修为去填）。
5. 达成任一结束条件（飞升 / 死亡 / 寿元耗尽 / 48 回合上限）即结算，给出结局、称号、评语与完整生平年表。

### 属性

| 属性 | 作用 |
| --- | --- |
| **修为 / 境界** | 主线。攒够突破阈值可以闭关冲关 |
| **灵根** | 修行速度倍率（0.70–1.75），开局随机，可重抽一次 |
| **出身** | 初始气运 / 道心 / 灵石 / 声望与初始 flag，共 9 种 |
| **气运** | 影响突破成功率与部分机遇的走向（气运高的人更容易撞上奇遇） |
| **道心** | 影响突破成功率。道心高走正道，道心低更容易滑向魔道 |
| **魔念** | 涨到 70 以上且境界不低，结局会变成「天魔人生」 |
| **寿元** | 年龄超过寿元即「寿元耗尽」而死；境界越高寿元上限越高 |
| **声望 / 灵石 / 贡献** | 影响部分事件的触发条件与结局称号 |
| **道侣 / 关系** | 6 位可遇角色（苏婉儿 / 沈青霜 / 顾长歌 / 江晚舟 / 姜雪璃 / 白芷）各有自己的线，可以结为道侣 |

### 境界与寿元

| 序 | 境界 | 突破所需修为 | 寿元上限 |
| --- | --- | --- | --- |
| 0 | 凡体 | 240 | 90 |
| 1 | 炼气 | 620 | 120 |
| 2 | 筑基 | 1290 | 200 |
| 3 | 金丹 | 1300 | 400 |
| 4 | 元婴 | 850 | 800 |
| 5 | 化神 | 900 | 1500 |
| 6 | 渡劫 | 2000 | 3000 |
| 7 | 飞升 | — | 无尽 |

> 中段两道巨关（筑基→金丹 1290、金丹→元婴 1300）筛掉大半人。过了元婴就是**应天劫**：化神之后突破成功率额外 -22%，走火了要拿寿元去填；最后一道「渡劫→飞升」要 2000，是全程唯一的巨额关。

### 六种结局

| 结局 | 档位 | 判定条件（简） |
| --- | --- | --- |
| **陨落** | 死亡 | 走到带 `death` 的选项上——没有免死金牌，选了就是选了 |
| **普通修仙者** | 普通 | 没成气候（凡体 / 炼气，或筑基却活不过 140 岁） |
| **凡人长寿** | 长寿 | 境界不高于筑基，却活到 140 岁以上 |
| **正常人生** | 正常 | 金丹 / 元婴——有一番修行，也有一场归宿 |
| **天魔人生** | 魔道 | 魔念 ≥ 58 且境界 ≥ 金丹，或带着魔念飞升 |
| **爽文人生** | 爽文 | 化神及以上（或元婴 + 声望 ≥ 185） |

结局只是六档标签，真正的差异在**称号**上：同样是「正常人生」，可能是「金丹真人」，也可能是「元婴老祖」；魔念深重者会被称「血海魔君」「万魔之尊」。

### 成就与图鉴

- **25 个成就**，含跨周目成就「六道皆历」（六家宗门全都待过）。
- 其中一个成就没有任何提示，只留给知道那个名字的人。
- **结局图鉴**记录每种结局达成的次数，未解锁的显示为「？」。
- 进度存在浏览器 `localStorage`（键名 `xiuxian.v1`），换设备不同步。

### 战绩图

结算页可以生成一张 **720×1280** 的水墨战绩图（canvas 绘制）：姓名、灵根出身、结局印章、五项关键属性、九条生平摘要。手机上长按保存，适合发群和朋友圈。

### 存档

每次事件结算后自动存档。中途关掉页面，下次打开标题页会出现「继续上一世」。

## 设计要点

几个刻意的取舍，都有原因：

- **盲选**：选项不标后果。危险只从正文的氛围与处境里透出来——这才像修仙，而不是点数值表。
- **正文只有约 50 字**：112 个事件的正文全部压在 42~52 字（中位 48）。一屏读完、节奏不拖，画面靠**一个**具体意象撑住，剩下的交给你的想象。
- **全随机开局 + 只给一次重抽**：出身和灵根不能自选，但给你一次改命的机会，让「重开」有分量。
- **会死，且死亡是独立结局**：不设血量与战斗，死亡来自**你选的选项**，通常每个致命事件都留着活路。
- **没有免死金牌**：不设血量、不设护符，气运也挡不住死。要让「陨落」占到三成左右，原先「气运 ≥ 65 捡回一条命」的保命机制必须去掉——你选的，就是你的命。
- **天劫惩罚**：化神之后成功率额外下降、失败扣寿元——让顶端晋升变成一场拿寿命换的赌博，而不是数值堆满就自动通关。
- **成本曲线的形状是算出来的**：模拟发现「整体抬价或降价」只会让所有人卡在同一个境界上（分布是阶跃的）。最终做成「中段两道巨关筛人 + 尾段 2000 的飞升巨关」，再叠上化神后的天劫惩罚，八个境界才都有人走到、而飞升稳定在 2% 左右。
- **一局 40 多回合**：单局能跑完，但事件池有 112 个，所以每一世看到的东西都不同。

## 目录结构

```
.
├── index.html              # 构建产物：单文件游戏，双击即玩（勿手改）
├── build.mjs               # 构建脚本：校验数据 + 内联 css/json/core/ui
├── .nojekyll               # 让 GitHub Pages 跳过 Jekyll
├── src/
│   ├── core.mjs            # 纯逻辑：境界/灵根/出身/结局/成就/Game 类，不碰 DOM
│   ├── ui.js               # 界面与存档层（IIFE，操作 DOM）
│   ├── style.css           # 水墨风样式
│   ├── template.html       # HTML 骨架，含 <!--STYLE--> <!--DATA--> <!--SCRIPT--> 占位符
│   └── data/
│       ├── SCHEMA.md       # 事件数据规范
│       └── d01..d06-*.mjs  # 112 个事件，纯数据、可 JSON 序列化、无函数
└── tools/
    ├── simulate.mjs        # 无界面平衡模拟器（random / greedy 两种策略）
    ├── sweep.mjs           # 数值参数扫描
    ├── ui-smoke.mjs        # 界面层冒烟测试（Node + DOM 桩）
    └── verify.mjs          # 产物自检（单文件 / 零依赖 / 数据完整）
```

**编辑的是 `src/`，`index.html` 是产物**。改完跑一次 `node build.mjs`。

## 开发与测试

需要 Node.js 18+（开发时用的是 v24）。没有第三方依赖，不需要 `npm install`。

```bash
node build.mjs              # 校验数据并重新生成 index.html
node tools/simulate.mjs 5000 # 跑 5000 局平衡模拟（random + greedy）
node tools/sweep.mjs 1500    # 数值参数扫描，输出对比表（★定稿 那一行就是线上参数，用作回归基准）
node tools/ui-smoke.mjs 40   # 界面冒烟测试：自动走完 40 个完整周目
node tools/verify.mjs        # 产物自检：单文件、零依赖、数据完整、脚本可求值
```

- `build.mjs` 会做**数据校验**：id 唯一、选项 ≥ 2、`cond` / `effect` 字段必须在白名单内、`sectJoin` 必须是已知宗门……任何一条不过就直接构建失败。
- `simulate.mjs` 输出结局分布、终局境界分布、平均回合/终龄、横死率、事件覆盖率、成就达成率。
- `ui-smoke.mjs` 用一套极简 DOM 桩在 Node 里跑通内联脚本，覆盖「取名 → 抽灵根 → 重抽 → 落定 → 事件 → 突破 → 结算 → 图鉴 → 分享图 → 再来一世」以及**刷新后继续上一世**的存档读回。
- `verify.mjs` 守住「单文件」这个承诺：确认产物里没有任何外部 `src`/`href`、没有 `@import`、JSON 块可解析、112 个事件 id 唯一、内联脚本无 `export`/`import` 残留且能在裸 DOM 桩下求值、`localStorage` 有 try/catch 兜底（`file://` 下不会白屏）。

> 受限沙箱里 Chromium 起不来（mojo named pipe 被拒），所以界面验证走的是 `ui-smoke.mjs` 这套 DOM 桩，而不是真实浏览器截图。

## 数值平衡

`node tools/simulate.mjs 5000` 随机策略（等同于一个不看提示、凭感觉乱选的玩家）的实测：

| 结局 | 实测 | 目标 |
| --- | --- | --- |
| 陨落（死亡） | 31.1% | 约 30% |
| 正常人生 | 19.8% | 约 20% |
| 爽文人生 | 18.7% | 约 20% |
| 凡人长寿 | 10.4% | 约 10% |
| 普通修仙者 | 10.0% | 约 10% |
| 天魔人生 | 9.9% | 约 10% |

终局境界：凡体 1.8% / 炼气 10.8% / 筑基 25.4% / 金丹 26.5% / 元婴 14.6% / 化神 10.8% / 渡劫 7.9% / 飞升 2.1%。

平均 39.6 回合、终龄 156、事件覆盖 112/112。八个境界都有人走到，飞升 2.1%——**爽文要稀罕才值钱**。

这组数字是 `tools/sweep.mjs` 扫了十几轮曲线和判定线选出来的：目标是「普通 10 / 长寿 10 / 正常 20 / 天魔 10 / 爽文 20 / 陨落 30」，实际六档与目标的偏差合计只有 3 个百分点。

所有平衡参数集中在 `src/core.mjs` 顶部的 `TUNING` 对象里，改完直接用 `tools/sweep.mjs` 扫参数对比，不用改代码。

## 事件数据格式

每个事件是一个纯数据对象，完整规范见 [`src/data/SCHEMA.md`](src/data/SCHEMA.md)。一个最小的例子：

```js
export const EVENTS_D03 = [
  {
    id: 'd03_23',              // 全局唯一
    title: '夜半叩门',
    text: '……正文，约 50 字（42~52）。',
    once: true,                // false 表示可重复出现
    weight: 20,                // 抽取权重
    cond: { realmMin: 1, flagNone: ['识得苏婉儿'] },   // 触发条件，字段有白名单
    choices: [
      { text: '开门',   result: '……', effect: { cult: 60, luck: -3, log: '开门' } },
      { text: '装作没听见', result: '……', effect: { mind: 4, log: '不闻' } }
    ]
  }
];
```

- `cond` 支持：`realmMin/Max`、`gender`、`sect`、`noSect`、`luckMin/Max`、`mindMin/Max`、`moMin/Max`、`fameMin/Max`、`ageMin/Max`、`cultMin`、`flagAll/Any/None`、`turnMin/Max`、`chance`。
- `effect` 支持：`cult`、`cultBase`、`luck`、`mind`、`mo`、`fame`、`wealth`、`lifespan`、`contribution`、`age`、`flagAdd/flagDel`、`sectJoin/sectLeave`、`partner`、`rel`、`realm`、`death`、`log`。
- 数据里**不能有函数**，必须可 JSON 序列化——因为构建时会整体内联成 `index.html` 里的一个 JSON 块。

## 部署与分享

游戏是单个 HTML 文件，扔到任何静态托管上就能用。仓库里已放好 `.nojekyll`，GitHub Pages 不会去跑 Jekyll。

### GitHub Pages

**方式一：仓库设置里点三下（推荐，最省事）**

1. 打开 `https://github.com/<用户名>/<仓库名>/settings/pages`
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 `/ (root)`，点 **Save**

等一分钟左右，访问 **`https://<用户名>.github.io/<仓库名>/`** 就是在线版。

本项目已经开启，线上地址：**<https://ydzd6.github.io/xiuxian-simulator/>**

**方式二：命令行（需要 `gh` 能正常联网）**

```bash
gh api -X POST repos/<用户名>/<仓库名>/pages \
  -f 'source[branch]=main' -f 'source[path]=/'
```

> 注意：本项目的开发环境里沙箱会让 `schannel` 拿不到凭据（`SEC_E_NO_CREDENTIALS`），**所有 HTTPS 请求都会失败**，所以 `gh` / `curl https://...` 在这里用不了；`git push` 走的是 SSH，不受影响。如果你的机器没有这个限制，两种方式都能用。

### 其他备选

- **Cloudflare Pages**：连接仓库，构建命令留空，输出目录填 `/`。
- **Netlify / Surge / 对象存储静态网站**：把 `index.html` 传上去即可，不需要任何构建。
- 最原始的办法：把 `index.html` 直接发给朋友，用浏览器打开也能玩（`localStorage` 有 try/catch 兜底，`file://` 下不会白屏）。

### 微信里分享

拿到 `https://` 链接后直接发给好友或发朋友圈，微信内置浏览器能打开。页面已经写好 `og:title` / `og:description` / `theme-color`，转发时会带标题和简介。几点注意——

1. GitHub Pages 在国内部分网络下加载偏慢。如果朋友打不开或很卡，换 Cloudflare Pages 或国内静态托管会明显更快。
2. 战绩图是 canvas 生成的 dataURL，微信里请**长按图片**保存，别指望「下载」按钮（微信内置浏览器会限制下载）。
3. 游戏进度存在浏览器本地（`localStorage`），换手机或清理缓存后进度不保留。
